BAB I 
PENDAHULUAN 
A. Latar Belakang
Keterbukaan informasi di lingkungan pengadilan merupakan hak 
konstitusional masyarakat yang dilindungi oleh undang -undang. Sejak 
diterbitkannya standar penilaian website terdahulu, lanskap digital telah 
mengalami perubahan masif. Website pengadilan tidak boleh lagi 
diposisikan pasif sebagai papan pengumuman elektronik berbasis teks 
yang kaku, melainkan harus bertransformasi menjadi portal pelayanan 
interaktif yang andal, aman, mudah diakses, serta responsif terhadap 
kebutuhan pencari keadilan di era modern. 
B. Maksud dan Tujuan
Petunjuk teknis ini dimaksudkan sebagai panduan baku bagi 
satuan kerja dalam memperbaharui struktur, infrastruktur, dan konten 
website. Tujuannya adalah menciptakan keseragaman standar website 
peradilan agama yang berkinerja tinggi, menjamin kebebasan inovasi 
teknologi di daerah dengan mengedepankan aspek keamanan siber 
nasional, serta menyederhanakan proses monitoring evaluasi internal 
melalui pemanfaatan sistem kecerdasan otomatisasi. 
C. Ruang Lingkup
Ruang lingkup petunjuk teknis ini mencakup pengelolaan dan 
keamanan infrastruktur teknologi informasi , standar website, identitas 
visual, dan struktur konten , serta evaluasi website melalui aplikasi 
SINOVA.

BAB II 
TATA KELOLA DAN KEAMANAN INFRASTRUKTUR 
TEKNOLOGI INFORMASI 
Untuk menjamin ketersediaan layanan ( availability), keutuhan data ( integrity), 
dan kerahasiaan ( confidentiality) dengan tetap memberikan ruang fleksibilitas 
inovasi di daerah, setiap satuan kerja wajib menerapkan standar infrastruktur 
sebagai berikut: 
A. Pemilihan dan Standar Keamanan Web Server
1. Fleksibilitas Penggunaan
Satuan kerja diberikan kebebasan penuh untuk memilih dan
menentukan jenis perangkat lunak Web Server (seperti Nginx, Apache
HTTP Server, LiteSpeed, atau perangkat sejenisnya) yang dinilai paling
sesuai dengan karakteristik beban server dan kapasitas infrastruktur
lokal (baik On-Premise, lingkungan virtualisasi Proxmox, maupun
Cloud).
2. Kewajiban Non-EOL
Syarat mutlak pemanfaatan perangkat lunak tersebut adalah versi
sistem operasi dan Web Server  yang dijalankan wajib berupa versi
stabil yang masih menerima dukungan pembaruan keamanan resmi
dari vendor pengembang (tidak berstatus End of Life / EOL).
3. Hardening Server
Pengelola server wajib mengkonfigurasi keamanan tingkat dasar,
meliputi penonaktifan penjelajahan direktori ( directory
indexing/listing) untuk mencegah paparan struktur arsip, serta
menyembunyikan informasi versi perangkat lunak yang digunakan
(server signature/tokens) guna meminimalkan celah eksploitasi.
B. Pemilihan dan Keamanan Aplikasi Pembangun (CMS dan Framework)
1. Fleksibilitas Sistem
Pengembangan dan pengelolaan tata muka website dapat dilakukan
secara mandiri menggunakan kerangka kerja ( Framework seperti
CodeIgniter, Laravel, dll.) maupun menggunakan Sistem Manajemen
Konten (Content Management System / CMS) publik seperti WordPress,
Joomla, atau Drupal.

2. Kewajiban Pembaruan
Seluruh core software  pembangun website wajib dipastikan berada
pada versi mutakhir dan mendapatkan patch keamanan berkala.
Migrasi wajib dilakukan segera apabila versi yang digunakan saat ini
masuk dalam kategori EOL atau tidak lagi didukung oleh
komunitas/vendor resmi.
3. Validasi Input dan Proteksi Login
Aplikasi berbasis Framework maupun CMS wajib menerapkan sanitasi
pada setiap form masukan (input validation) untuk mencegah eksekusi
skrip berbahaya seperti SQL Injection atau XSS. Halaman administratif
(backend login) wajib dilindungi dengan metode pembatasan percobaan
gagal ( rate limiting/brute -force protection ) dan penggunaan sistem
Captcha dan/atau mengaktifkan fitur MFA ( Multi Factor
Authentication).
C. Kebijakan Komponen Pihak Ketiga (Plugin & Ekstensi)
1. Syarat Legalitas dan Keamanan
Penggunaan plugin, modul tambahan, ekstensi, atau pustaka skrip
(library) pihak ketiga ( third-party) diperbolehkan untuk menunjang
fungsionalitas inovasi layanan. Namun, satuan kerja wajib
memastikan bahwa seluruh komponen tersebut diunduh hanya dari
saluran/repositori resmi pengembang dan memiliki lisensi yang sah.
2. Larangan Piranti Bajakan
Dilarang keras menggunakan perangkat lunak hasil modifikasi ilegal
(nulled plugins/themes ) atau bajakan, karena berisiko tinggi
mengandung sisipan kode perusak (malware/backdoor).
3. Audit Berkala
Tim IT satuan kerja wajib melakukan pemantauan dan pembaruan
plugin secara berkala untuk menutup kerentanan keamanan yang
ditemukan.
D. Sistem Keamanan Jaringan dan Akses Lanjutan
1. Manajemen Port
Hanya port esensial yang diizinkan terbuka untuk lalu lintas publik,
yakni Port 80 (HTTP) dan 443 (HTTPS). Port lainnya wajib ditutup
secara otomatis (default deny) dari lalu lintas luar.

2. Akses Kontrol Jarak Jauh Terproteksi
Jalur akses jarak jauh administrator (SSH/RDP) dilarang
menggunakan port standar. Sangat direkomendasikan agar akses
administrasi server dikunci ( lockdown) hanya melalui jaringan Virtual
Private Network (VPN) atau daftar putih alamat IP (IP Whitelisting).
3. Web Application Firewall (WAF)
Satuan kerja wajib mengimplementasikan lapisan pelindung WAF
untuk menepis anomali serangan siber berbasis web.
E. Manajemen Keamanan Basis Data (Database)
1. Isolasi Jaringan Database
Layanan basis data (MySQL, MariaDB, PostgreSQL, d an lain -lain)
dilarang diekspos secara langsung ke jaringan publik ( internet) dan
hanya boleh melayani interaksi dari jaringan internal ( bind-address
127.0.0.1 / localhost).
2. Pemisahan Kredensial
Dilarang menggunakan pengguna utama bawaan ( default root user )
untuk koneksi basis data website. Setiap aplikasi/ website harus
memiliki kredensial pengguna basis data tersendiri dengan kata sandi
kompleks dan hak akses (privileges) yang dibatasi secara spesifik.
F. Enkripsi dan Proteksi Transmisi Data (SSL/TLS)
1. Kewajiban HTTPS
Seluruh lalu lintas data komunikasi website wajib dienkripsi penuh
menggunakan sertifikat SSL/TLS yang valid. Protokol HTTP tak
terenkripsi (Port 80) wajib diarahkan (force redirect) secara otomatis ke
HTTPS (Port 443).
2. Protokol Mutakhir
Pengelola server wajib menonaktifkan dukungan terhadap protokol
enkripsi yang telah usang dan rentan (seperti SSLv3, TLS 1.0, dan TLS
1.1), serta menjamin kompatibilitas minimal pada protokol TLS 1.2
atau yang lebih baru.
G. Pencadangan (Backup) dan Pemantauan (Monitoring)

BAB III 
STANDAR WEBSITE, IDENTITAS VISUAL, DAN STRUKTUR KONTEN 
Untuk memastikan pelayanan informasi yang prima, pengadilan wajib 
memedomani standar tata kelola dan pedoman struktur konten website sebagai 
berikut: 
A. Prinsip Pengelolaan Website
1. Aksesibilitas
Website harus dapat diakses dengan mudah pada berbagai jenis
sambungan internet. Website juga harus memenuhi standar
aksesibilitas internasional agar dapat digunakan oleh seluruh
pengguna, termasuk penyandang disabilitas (kelompok rentan).
2. Komunikatif / Informatif
Informasi yang disajikan harus mudah dipahami, relevan, dan
memberikan manfaat bagi masyarakat pencari keadilan secara ringkas
dan tidak menimbulkan ambiguitas.
3. User Friendly
Navigasi, struktur menu, tampilan konten, dan fitur pencarian harus
disusun secara logis sehingga pengguna dapat menemukan informasi
dengan cepat.
4. Estetis
Website harus memiliki desain visual yang menarik, konsisten, dan
mencerminkan wibawa lembaga Peradilan Agama.
5. Ekonomis
Menghindari penggunaan elemen berat seperti animasi berlebihan
atau live streaming  langsung pada halaman utama yang dapat
memperlambat akses bagi masyarakat di daerah dengan jaringan
internet terbatas.

B. Pedoman Dasar dan Identitas Visual Website
1. Identitas Warna Peradilan Agama
Pengelolaan layout dan template antarmuka ( User Interface ) website
wajib memedomani identitas visual kelembagaan dengan
menggunakan kombinasi warna standar, yakni Warna Utama
(Primary): #056e4f dan Warna Sekunder (Secondary): #ff9900.
2. Alamat Website
Menggunakan domain resmi pemerintah yaitu .go.id sesuai ketentuan
penggunaan domain bagi instansi pemerintah.
3. Keandalan Hosting
Dilarang keras menggunakan layanan alamat website atau hosting
gratis (seperti blogspot.com, wordpress.com, dan sejenisnya). Satuan
kerja wajib memastikan pembayaran langganan Hosting maupun
Internet Service Provider (ISP) tepat waktu.
4. Penggunaan Server Internal
Penggunaan server lokal pengadilan untuk hosting website
diperbolehkan selama dipisahkan dari server aplikasi internal (seperti
SIPP) dan dilindungi oleh firewall yang ketat.
C. Prinsip Desain Halaman Depan (Front Page)
Desain halaman depan (beranda) harus mencerminkan profesionalitas
dan pelayanan publik dengan prinsip:
1. Sederhana, jelas, dan mudah dinavigasi
Tampilan tidak terlalu ramai dan informasi utama (seperti SIPP dan
Jadwal Sidang) dapat ditemukan dalam 2 (dua) klik atau kurang.
2. Responsif di berbagai perangkat
Tampilan harus optimal pada desktop, tablet, dan ponsel ( Mobile
Responsiveness).
3. Profesional dan konsisten
Menggunakan font, ikon, dan tipografi yang konsisten selaras dengan
identitas lembaga. Menghindari slider yang terlalu berat (maksimal 3-
5 slide).
4. Aksesibilitas untuk semua
Menggunakan kontras warna yang baik, memberikan alt text pada
gambar, serta menyediakan fitur perbesar teks tanpa merusak layout.

BAB IV 
INDIKATOR MONITORING DAN EVALUASI WEBSITE MELALUI 
APLIKASI SINOVA 
Proses monitoring, evaluasi, dan penilaian kepatuhan penyediaan menu website 
satuan kerja dilakukan sepenuhnya secara digital menggunakan platform

B. Alur Mekanisme Penilaian Mandiri
Penilaian dilaksanakan dengan prosedur asinkron sebagai berikut:
1. Operator satuan kerja pengadilan tingkat pertama menginputkan URL
tautan spesifik sesuai dengan indikator pada aplikasi SINOVA.
2. Sistem SINOVA menginisialisasi sistem untuk memverifikasi URL dan
mengambil gambar tangkapan layar ( screenshot) secara otomatis
sebagai bukti visual (visual evidence).
3. Bukti visual tersebut dikunci dalam sistem sebagai dasar penilaian
tingkat banding.
C. Verifikasi Tingkat Banding dan Ketentuan Nilai Baku
1. Tim penilai Pengadilan Tinggi Agama / Mahkamah Syar'iyah Aceh
memverifikasi indikator menggunakan metode perbandingan visual
pada SINOVA.
2. Pemberian nilai dilakukan secara baku, yaitu:  10 (Sempurna), 5
(Kurang Lengkap/Perlu Perbaikan), atau 0 (Tidak Sesuai/Tautan
Rusak). Pemberian nilai 5 (Kurang Lengkap/Perlu Perbaikan) wajib
disertai dengan argumentasi/catatan perbaikan di dalam sistem.
3. Untuk kategori tertentu, pemberian nilai dengan pilihan Ya (nilai
penuh) atau Tidak (nilai kosong).
D. Prosedur Penyelesaian Sanggah Nilai
1. Satuan Kerja Tingkat Pertama
Pengadilan Agama (PA) melakukan pengajuan sanggahan dilakukan
melalui aplikasi SINOVA dengan menyertakan argumen sebelum masa
sanggah berakhir.
2. Satuan Kerja Tingkat Banding
Pengadilan Tinggi Agama (PTA) meninjau kembali pengajuan tersebut
dan berwenang untuk menerima atau menolak sanggahan.
3. Direktorat Jenderal Badan Peradilan Agama (Ditjen Badilag)
Apabila sanggahan ditolak oleh PTA, Satuan Kerja dapat memilih opsi
"Eskalasi ke Pusat". Ditjen Badilag akan meninjau riwayat sanggahan
untuk memberikan keputusan penilaian final. Ditjen Badilag
